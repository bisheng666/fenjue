先说清楚一件事，免得你白等：

  ✗ 我不能在 Windows 上直接生成 macOS 的程序。
    PyInstaller 官方明确不支持交叉编译 ——
    macOS 的 .app 必须在 macOS 上打包，这是 Apple 的格式限制。

  ✓ 但下面三条路都能拿到，其中「路线 A」你完全不需要有 Mac。


────────────────────────────────────────
  路线 A：GitHub 免费云打包（推荐，零成本，不需要 Mac）
────────────────────────────────────────

  原理：GitHub 免费提供真实的 Apple Silicon（M1/M2）机器，
        你把代码传上去，它帮你打包，你下载 .app 就行。

  成本：0 元。公开仓库完全免费，私有仓库每月也有 2000 分钟免费额度，
        这个打包一次只花 3~5 分钟。

  ───── 具体步骤 ─────

  【第 1 步】注册 GitHub

     打开 https://github.com/signup
     邮箱 + 密码 + 用户名，验证一下就好。

  【第 2 步】新建一个仓库

     登录后点右上角 "+" → "New repository"

     仓库名随便起，比如  fenjue
     可见性选  Public（公开）—— 这样完全免费
     其他都不用勾，点最下面的 "Create repository"

  【第 3 步】上传代码

     创建完会跳到一个空仓库页面，中间有一行提示：
       "uploading an existing file"  ← 点这个链接

     然后：
       · 把我给你的 焚决-mac源码.zip 解压出来
       · 把解压后的【所有东西】拖进浏览器的上传框
       · 页面底部填个说明，点 "Commit changes"

     ★ 关键难点：.github 是个隐藏文件夹（名字以点开头），
       Windows 资源管理器默认不显示它！

       有两个办法，任选其一：

       办法甲（更稳）：先只上传看得见的文件
         1. 把 fenjue_web.py、web 文件夹、mac 文件夹、说明.txt 拖上去
         2. 点 "Commit changes"
         3. 回到仓库主页面，点 "Add file" → "Create new file"
         4. 文件名框里输入（斜杠会自动建文件夹）：
              .github/workflows/build-macos.yml
         5. 把 mac/github工作流.yml 里的全部内容复制粘贴进去
         6. 点 "Commit changes"
         这次提交会触发打包。

       办法乙：让 Windows 显示隐藏文件
         打开那个源码文件夹 → 上方「查看」标签
         → 勾选「隐藏的项目」
         这时 .github 会出现，再一起拖上去。

  【第 4 步】等它自动打包

     上传完点上面的 "Actions" 标签页。
     会看到一条黄色的 "打包 macOS 版（M 芯片）" 正在跑。

     如果没自动跑：
       · 点左边的 "打包 macOS 版（M 芯片）"
       · 右边点 "Run workflow" → 绿色按钮
       · 刷新页面等几秒

     整个流程约 3~5 分钟。看到绿色对勾就是成功了。

  【第 5 步】下载

     点进那次运行（绿色对勾那条）
     拉到页面最下面，找到 "Artifacts" 区域
     点 焚决提示词库-macOS-arm64 下载

     得到的是一个 zip，解压后：
       焚决提示词库.app        ← 双击就能用
       焚决数据/              ← 你的提示词
       怎么打开.txt

  ───── 打开时的两个坑 ─────

  坑1：会被系统拦下来
      提示「无法打开，因为无法验证开发者」
      → 右键点图标 → 选「打开」→ 弹窗里再点「打开」
      → 只需要做一次，以后正常双击

  坑2：提示「已损坏，无法打开」
      这是 macOS 给未签名程序的"礼貌说法"，不是真损坏。
      → 打开「终端」，执行：
           xattr -cr "/路径/焚决提示词库.app"
        （把 /路径/ 换成实际位置，也可以直接把 .app 拖进终端自动填路径）
      → 然后再双击

  Mac 版和 Windows 版有什么区别？
════════════════════════════════════════════════════════

功能完全一样：
  · 31 条提示词，点一下复制（自动带前缀尾缀）
  · 9 套配色、壁纸、毛玻璃、透明度
  · 拖动排序、右键菜单、搜索
  · 导入导出备份

唯一区别是窗口外观：

  Windows 版   无边框 + 自绘标题栏 + 自绘右上角三个按钮
               （很定制的风格）

  macOS 版     原生标题栏，左上角红黄绿三个按钮
               （苹果用户习惯的样子，也符合 Apple 人机界面规范）

  为什么这么改：Mac 上自己画一套窗口按钮，苹果用户看着会很别扭。
  而且原生标题栏的全屏、拖拽、Mission Control 都由系统接管，更稳。

数据文件格式完全一致：
  Mac 上产生的 prompts.json 可以直接拷到 Windows 上用，反之亦然。

  跨平台改造做了什么（技术说明，不看也行）
════════════════════════════════════════════════════════

  改造前的三处 Windows 专有代码：

  1. 剪贴板
     原来：ctypes 直接调 user32/kernel32
     现在：按平台分发
         Windows → user32（原地保留）
         macOS   → pbcopy（系统自带，零依赖）
         Linux   → wl-copy / xclip / xsel

  2. 打开数据文件夹
     原来：os.startfile()（Windows 专有）
     现在：Windows → os.startfile
         macOS   → open
         Linux   → xdg-open

  3. 路径处理
     原来：数据目录放在 exe 同级
     现在：macOS 的 .app 是个文件夹，数据放进去用户找不到，
         所以自动往上退三层，回到 .app 所在的目录。
         同时网页资源会在 Contents/Resources 和
         Contents/Frameworks 两处都找一遍。

  4. 窗口风格
     原来：无条件用无边框窗口
     现在：只有 Windows 用无边框；macOS/Linux 用原生标题栏，
         并且前端会自动隐藏自绘标题栏和那三个窗口按钮。

  ★ 关于 pyobjc 的一个坑（我已经在脚本里处理了）
  ────────────────────────────────────────

  pywebview 在 macOS 上依赖 6 个 pyobjc 包：
      pyobjc-core / -Cocoa / -Quartz / -WebKit
      pyobjc-framework-security / -UniformTypeIdentifiers

  更麻烦的是：PyInstaller 没有 pyobjc 的专用 hook。
  如果不显式声明，PyInstaller 可能漏掉 objc 框架，
  打出来的 .app 双击会立刻退出，报：
      ModuleNotFoundError: No module named 'objc'

  所以我在两处都做了防线：
    · build-mac.sh 里 pip 装全 6 个包，装完立刻 import 验证
    · PyInstaller 命令里加 8 个 --hidden-import
    · 打包完再检查 .app 里有没有 objc 相关文件（< 4 个就报错停下）

  如果你自己改脚本，这三处防线别删。


  如果路线 A 报错了
════════════════════════════════════════════════════════

  把 Actions 页面里红色的那一步展开，把报错信息发我。
  常见的有：

  · "No such file or directory: web/index.html"
    → 上传时漏了 web 文件夹，重新传完整

  · "No module named pyobjc"
    → 依赖没装成功，重跑一次通常就好

  · YAML 语法错误（页面直接提示 workflow 无效）
    → 上传时 build-macos.yml 被改坏了，重新下载我给的原始文件

  · 找不到 .github 文件夹
    → Windows 默认隐藏了，去文件夹选项里打开「显示隐藏文件」

  · 第 5 步 "验证 pyobjc 能 import" 失败
    → 说明 pyobjc 没装好，继续打包也是白搭。
      多数是 Python 版本问题（建议 3.10~3.12）。
      如果用的是 3.13 或更新的，试着改成 3.12 重跑。

  · 第 7 步 "pyobjc 是否打进包" 命中不足 4 个
    → PyInstaller 没收集到 objc 框架。
      把该步骤的完整输出发我，我调 hidden-import 列表。
